PREGUNTA 1

El error "numero tarjeta no encontrado en la sesion" se produce porque la
sesion donde se guardo el numero de tarjeta no esta disponible para la
instancia que recibe la peticion final (GET /visaApp/pago/).

Causas concretas:

1. El balanceador esta configurado con StickySession=(None) (visible en la
   captura del balancer-manager) y Method=byrequests. Esto significa que
   cada peticion HTTP del cliente se distribuye en round-robin entre las 3
   instancias del cluster, sin ninguna afinidad por cliente.

2. La aplicacion P1-base esta configurada con
   SESSION_ENGINE = "django.contrib.sessions.backends.cache", que usa
   LocMemCache. LocMemCache es un cache en memoria local de cada proceso
   Django, por lo que NO se comparte entre las 3 instancias del cluster.

3. El flujo del pago tiene varias peticiones consecutivas:
   - GET  /visaApp/tarjeta/  (mostrar formulario tarjeta)
   - POST /visaApp/tarjeta/  (guardar numeroTarjeta en request.session)
   - GET  /visaApp/pago/     (leer numeroTarjeta de request.session)
   Sin sticky session, estas peticiones caen en instancias distintas. La
   instancia que guarda el numero de tarjeta en su LocMemCache no es la
   misma que atiende la peticion siguiente, asi que esta no encuentra la
   clave en sesion y muestra el error.

Esto se confirma con la captura "despues": las 3 instancias tienen
Elected=1 cada una, lo que demuestra que las peticiones del flujo fueron
repartidas round-robin (una por instancia).


PREGUNTA 2

Respuesta correcta: d) Ninguno. No se envia ninguna cookie desde el
balanceador.

Justificacion: la cookie ROUTEID solo se inyecta cuando el balanceador
tiene activada la afinidad de sesion (sticky session) y existe la
directiva
    Header add Set-Cookie "ROUTEID=.%{BALANCER_WORKER_ROUTE}e; path=/"
        env=BALANCER_ROUTE_CHANGED
Como en la captura aparece StickySession=(None), Apache no esta marcando
ninguna afinidad de cliente y por tanto no anyade la cookie ROUTEID a la
respuesta. Las opciones a, b y c (.Instance01/02/03) solo serian validas
con sticky session activo.


PREGUNTA 3

1. Editar la configuracion del balanceador
   (/etc/apache2/sites-available/000-default.conf) anyadiendo:

       <Proxy "balancer://si2cluster">
           BalancerMember http://192.168.1.101:18000 route=Instance01
           BalancerMember http://192.168.1.101:28000 route=Instance02
           BalancerMember http://192.168.1.101:38000 route=Instance03
           ProxySet stickysession=ROUTEID
       </Proxy>

       Header add Set-Cookie "ROUTEID=.%{BALANCER_WORKER_ROUTE}e; path=/" \
           env=BALANCER_ROUTE_CHANGED

2. Verificar y recargar Apache:
       sudo apachectl configtest
       sudo systemctl reload apache2

3. Borrar las cookies del navegador (para que no quede una ROUTEID
   "fantasma" de pruebas anteriores).

4. Repetir el flujo de pago. Ahora todas las peticiones del flujo iran a
   la misma instancia (la que asigne la primera peticion), la sesion se
   conservara y el pago se registrara correctamente. En balancer-manager
   se vera que solo una instancia incrementa el contador Elected para
   ese cliente, y en DevTools del navegador aparecera la cookie ROUTEID
   con valor .Instance0X.
